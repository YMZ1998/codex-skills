# git-commit

`git-commit` 用于快速分析当前改动、选择提交范围并生成简体中文提交信息。工作流尽量压缩为两次命令调用：第一次检查并确定范围，第二次提交并验证。

## 提交范围

- 存在已暂存文件时，只提交已暂存内容，不再执行任何 `git add`。
- 没有已暂存文件时，执行 `git add -u`，暂存所有已追踪文件的修改和删除。
- 未追踪文件不会被自动加入提交。
- 用户明确要求“所有文件”时，才会加入未追踪文件。
- 没有可提交内容时停止，不创建空提交。

检查阶段不执行任何 `git diff` 查询，只解析 `git status --porcelain=v1` 的状态码和文件名。提交信息根据文件状态、文件名、最近提交风格和用户补充说明生成。

## 提交信息

首行格式：

```text
<类型>: <一句话概述>
```

类型包括 `feat`、`fix`、`docs`、`style`、`refactor`、`test` 和 `chore`。只有在确实有助于理解时才添加正文要点。末尾固定追加：

```text
Commit-By: Codex, GPT-5
```

## 使用

```text
使用 $git-commit 提交当前改动
```

补充说明会作为提交信息的参考：

```text
使用 $git-commit 提交当前改动，补充说明：整理技能安装文档
```

## 安全边界

技能不会执行 `git commit --amend`、新建分支或切换分支。只有用户明确要求推送时，才会在提交成功后执行 `git push`。仓库存在未解决冲突或正在进行 merge/rebase 时，它会停止并提示先处理仓库状态。

多行提交正文使用真实换行，避免 PowerShell 单引号把 `` `n `` 写成普通文本。
